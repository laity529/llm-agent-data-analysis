# 整合说明（开发笔记）

本项目整合了两次实践的内容，记录各模块的来源与分工，便于回溯设计决策。

## 整合了什么

**day7《数据分析 Agent》** 提供整体架构（保留）：

- `llm.py`：ChatOpenAI 模型配置，temperature=0（数据分析要求稳定、不发散）
- `tools/`：7 个工具 —— read_csv / sql_query / stats_summary / stats_value_counts / stats_group_agg / make_chart / calculator
- `agent.py`：`create_agent` 一行创建智能体，框架托管「调工具 → 回填 → 继续」循环
- `api.py`：FastAPI 后端，`/health` `/chat` 与 charts 静态目录
- `app.py`：Streamlit 前端，CSV 上传、聊天、图表展示

**day4《聊天机器人》** 提供会话体验（融入）：

- 多会话管理：新建会话、侧边栏历史列表、点击切换、第一条提问作为标题
- 「字典 + `get_session_history(session_id)`」的会话记忆模式

## 整合后的分工

**memory.py**（新增，整合核心）

- day4 的 sessions 字典 + `get_session_history` 模式
- day7 的「存 Agent 完整消息列表（含工具消息）」实现
- 会话元数据（标题、创建时间）
- 对外提供：get_messages / save_messages / list_sessions / delete_session

**agent.py**（改造）

- 记忆从本文件的 `_sessions` 改为调用 memory.py
- 会话标题在拼入「（当前数据文件: ...）」前缀之前生成，保持标题干净
- 数据文件路径从「拼进问题文本」改为 `chat()` 的独立参数 `data_file`

**api.py**（扩展）

- 新增 `/sessions`（列表）、`/sessions/{id}`（历史）、`DELETE /sessions/{id}`（删除），把 day4 侧边栏的数据源搬到后端

**app.py**（合并）

- 侧边栏 = day4 的会话管理 + day7 的文件上传与示例问题
- 聊天区 = 历史从后端拉取（后端是唯一真实源），本轮回答即时渲染
- 效果：刷新页面、切换会话，历史与图表都不丢失（day7 原版切换会话记录会串）

## 环境说明

依赖版本见 `requirements.txt`。模型在 `llm.py` 中通过 `model=` 指定，更换模型只需改这一个字符串后重启。

模型平台在「开通模型」同步期间偶发 `403 AccessDenied`（请求被分到尚未同步开通的实例），`agent.py` 已做 3 次自动重试。
